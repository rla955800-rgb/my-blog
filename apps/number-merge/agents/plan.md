# Plan 서브에이전트 지침 — 숫자 합치기 퍼즐

## 역할

웹앱 구현 계획(spec)을 작성한다. **코드는 작성하지 않는다.**

## 수정 가능한 범위

- `apps/number-merge/spec.md` 파일 하나만 새로 만든다.
- 그 밖의 파일은 읽기만 한다.

## 사용자 요청

> 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임. 점수판도 넣어줘.

## 전제와 제약

- 저장소: 마크다운 블로그 + 미니 웹앱 포트폴리오 (`CLAUDE.md` 참고). 순수 HTML, CSS, JavaScript만 사용, 빌드 도구 없음.
- 웹앱은 `apps/number-merge/` 안에서 자체 완결되어야 한다 (블로그의 `css/`, `js/`를 import하지 않음).
- 외부 라이브러리는 최소화. 이 게임은 라이브러리 없이 만드는 것을 기본으로 한다.
- 모바일에서도 플레이 가능해야 한다 → 방향키 + 터치 스와이프 모두 지원. 360px 폭에서 가로 스크롤 없음.
- 독창성: 슬라이드·합치기라는 **장르 메커니즘**만 사용한다. 특정 기존 게임의 이름, 로고, 고유 색상 팔레트(베이지/주황 계열 타일), 레이아웃을 그대로 따라 하지 않는다. 앱 제목은 "숫자 합치기"(가제)로 하고, 색상은 이 앱만의 팔레트를 정한다.
- 블로그와 어울리게: 라이트/다크 모드(`prefers-color-scheme`) 지원, 색상은 CSS 변수 토큰으로, `prefers-reduced-motion` 존중, `<html lang="ko">`, 키보드 접근성.
- 나중에 블로그 메인에 iframe 카드로 임베드될 예정 → iframe 안에서 방향키가 페이지 스크롤을 일으키지 않도록 고려.

## spec.md에 담을 내용

1. **개요**: 앱 이름, 한 줄 설명
2. **게임 규칙**: 보드 크기, 새 타일 생성 규칙(값과 확률), 이동·합치기 규칙(한 번 이동에 타일 하나는 한 번만 합쳐짐), 점수 계산, 승리 조건(목표 타일과 이후 계속하기 여부), 패배 조건
3. **화면 구성**: 헤더(제목, 현재 점수, 최고 점수), 보드, 버튼(새 게임 등), 승리/패배 안내 오버레이. 간단한 와이어프레임(텍스트)
4. **조작**: 방향키, WASD(선택), 터치 스와이프(최소 이동 거리 기준), 버튼 키보드 포커스
5. **점수판**: 현재 점수, 최고 점수(`localStorage`, `try/catch`), 점수 증가 표시 여부
6. **디자인**: 색상 토큰 목록(라이트/다크), 타일 값별 색 규칙, 글꼴, 애니메이션(이동/등장/합치기 — 최소한으로)
7. **파일 구조**: `apps/number-merge/` 아래 파일 목록과 각 파일의 책임 (예: `index.html`, `style.css`, `game.js`(순수 로직), `ui.js`(렌더링·입력) 등). 로직과 UI 분리.
8. **핵심 로직 설계**: 데이터 구조, 주요 함수 목록과 시그니처
9. **블로그 임베드 계획**: 카드에 들어갈 제목·설명, iframe 또는 미리보기 이미지 중 무엇을 쓸지 제안 (실제 임베드는 이번 단계에서 하지 않음)
10. **검증 항목**: Review 단계에서 확인할 체크리스트 (규칙 엣지 케이스 예: `[2,2,2,2]` → `[4,4,_,_]`, `[2,2,4,_]` → `[4,4,_,_]`, 이동 불가 방향이면 타일 생성 안 함 등)
11. **범위 밖**: 이번에 하지 않을 것 (예: 되돌리기, 랭킹 서버)

## 작성 규칙

- 한국어, 간결하게. 불확실하거나 사용자가 정해야 할 것은 "결정 필요" 항목으로 맨 끝에 모은다.
- 작성을 마치면 spec.md 경로와 "결정 필요" 항목만 짧게 보고한다.
