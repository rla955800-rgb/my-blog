# 숫자 합치기 (가제) — 구현 계획

## 1. 개요

- **앱 이름**: 숫자 합치기 (가제)
- **한 줄 설명**: 방향키나 스와이프로 숫자 타일을 한쪽으로 밀어, 같은 숫자끼리 합쳐 더 큰 숫자를 만드는 퍼즐.
- 위치: `apps/number-merge/` (자체 완결, 블로그의 `css/`, `js/`를 import하지 않음, 외부 라이브러리 없음)

## 2. 게임 규칙

| 항목 | 규칙 |
| --- | --- |
| 보드 | 4×4 (상수 `SIZE = 4`로 두어 변경 가능하게) |
| 시작 | 빈 칸 중 무작위 2곳에 타일 2개 생성 |
| 새 타일 | 유효한 이동 후 빈 칸 하나에 1개 생성. 값 `2`(90%) / `4`(10%) |
| 이동 | 선택한 방향 끝까지 모든 타일이 미끄러짐 |
| 합치기 | 이동 방향의 **앞쪽부터** 처리. 같은 값 두 타일이 만나면 합쳐짐. 한 번 이동에서 **한 타일은 한 번만** 합쳐짐 (`[2,2,2,2]` → `[4,4,_,_]`, `[4,4,8,_]` → `[8,8,_,_]`) |
| 유효 이동 | 이동 후 보드가 이전과 같으면 무효 → 타일 생성 없음, 점수 변화 없음, 턴으로 치지 않음 |
| 점수 | 합쳐서 생긴 타일 값의 합만큼 증가 (`2+2` → +4) |
| 승리 | `2048` 타일을 처음 만들면 승리 오버레이 표시. "계속하기"를 누르면 이어서 진행하며, 같은 게임에서 다시 승리 안내를 띄우지 않음 |
| 패배 | 빈 칸이 없고, 가로·세로로 인접한 같은 값도 없으면 게임 종료 |

## 3. 화면 구성

```
┌──────────────────────────────┐
│ 숫자 합치기                   │  ← h1
│ ┌────────┐ ┌────────┐        │
│ │ 점수    │ │ 최고    │ [새 게임]│
│ │ 1,240  │ │ 5,880  │        │
│ └────────┘ └────────┘        │
│ 같은 숫자를 밀어 합쳐 2048을…  │  ← 짧은 안내(한 줄)
│ ┌──────────────────────────┐ │
│ │  2 │    │  4 │    │        │
│ │────┼────┼────┼────│        │
│ │    │  8 │    │  2 │        │  ← 보드 (정사각형)
│ │ …                        │ │
│ │   [승리/패배 오버레이]     │ │
│ └──────────────────────────┘ │
│ 방향키·WASD·스와이프로 이동    │  ← 조작 안내(muted)
└──────────────────────────────┘
```

- 시맨틱: `<header>`(제목+점수판+버튼), `<main>`(보드), `<footer>`(조작 안내)
- 보드: 폭 `min(100%, 440px)`, `aspect-ratio: 1`, 가운데 정렬. 360px 화면에서 좌우 16px 여백 안에 들어감
- 오버레이: 보드 위에 반투명 배경 + 문구 + 버튼
  - 승리: "2048을 만들었어요!" + [계속하기] [새 게임]
  - 패배: "더 이상 움직일 수 없어요" + 최종 점수 + [다시 하기]
  - 열리면 첫 버튼에 포커스, 닫히면 보드로 포커스 복귀. 오버레이가 열린 동안 방향키 이동은 무시
- 접근성: 보드는 `role="grid"`가 아닌 단순 구조 + 보이지 않는 `aria-live="polite"` 영역에 "점수 1,240. 2048 달성" 같은 **중요 상태만** 알림 (매 이동마다 읽지 않음)

## 4. 조작

- **방향키**: ↑ ↓ ← → 로 이동. 게임이 처리한 키는 `preventDefault()` (페이지/부모 스크롤 방지)
- **WASD**: 함께 지원 (대소문자 무관). 입력창이 없으므로 충돌 없음
- 수정키(Ctrl/Alt/Meta)가 눌린 경우는 무시해 브라우저 단축키를 막지 않음
- 키 리스너는 `document`에 등록하되, 포커스가 버튼에 있어도 방향키는 게임 이동으로 처리 (Enter/Space는 버튼 동작 유지)
- **터치 스와이프**: 보드에서 `pointerdown`~`pointerup`(또는 touch 이벤트) 사이 이동 거리
  - 최소 거리 **30px** 이상, 가로/세로 중 절댓값이 큰 축을 방향으로 결정
  - 보드에 `touch-action: none`, 페이지에 `overscroll-behavior: none`으로 당겨서 새로고침·스크롤 방지
- **버튼**: 모두 `<button type="button">`, 최소 44×44px, `:focus-visible` 표시
- 연속 입력: 애니메이션 중에도 입력을 받아 즉시 최신 상태로 반영(입력 막지 않음)

## 5. 점수판

- **현재 점수**: 매 이동 후 갱신, 천 단위 구분(`toLocaleString('ko-KR')`)
- **최고 점수**: 현재 점수가 넘어서면 즉시 갱신 후 `localStorage` 키 `number-merge:best`에 저장. 읽기/쓰기 모두 `try/catch` (막히면 세션 동안만 메모리에 유지)
- **점수 증가 표시**: 점수 상자 위로 `+N`이 잠깐 떠오르는 효과 (reduced-motion이면 표시 생략) — "결정 필요" 참고
- (선택) 진행 중인 게임 상태 저장은 범위 밖 — "결정 필요" 참고

## 8. 핵심 로직 설계

### 데이터 구조

```js
// 타일: 애니메이션 추적을 위해 id를 가진다
Tile = { id: number, value: number, row: number, col: number,
         mergedFrom: [id, id] | null, isNew: boolean }

// 상태: 불변으로 다룸
State = {
  size: 4,
  tiles: Tile[],          // 보드 위 타일 목록
  score: number,
  won: boolean,           // 2048 달성 여부
  keepPlaying: boolean,   // 승리 후 계속하기 선택 여부
  over: boolean,          // 패배 여부
  nextId: number,
}

Direction = 'up' | 'down' | 'left' | 'right'
```

### 주요 함수 (`game.js`)

```js
createGame(size = 4, random = Math.random) → State          // 타일 2개로 시작
move(state, direction, random = Math.random) → { state, moved, gained }
                                                             // 무효 이동이면 moved=false, 원래 state 반환
slideLine(values: (number|null)[]) → { line, gained, merges } // 한 줄을 앞쪽으로 밀고 합침 (테스트 핵심)
toGrid(state) → (Tile|null)[][]                              // tiles → 2차원 배열
emptyCells(state) → { row, col }[]
addRandomTile(state, random) → State                         // 2(90%)/4(10%)
canMove(state) → boolean                                     // 빈 칸 또는 인접 동일값 존재
hasWon(state) → boolean                                      // 2048 이상 타일 존재
continueGame(state) → State                                  // keepPlaying = true
```

- 방향 처리: 각 줄을 이동 방향 기준 "앞→뒤" 순서로 뽑아 `slideLine`에 넣고 결과를 다시 배치 (방향별 좌표 변환 함수 하나로 통일)
- `random` 주입으로 콘솔/테스트에서 결과를 재현 가능하게

### `storage.js`

```js
loadBest() → number      // 실패·이상값이면 0
saveBest(score) → void   // 실패해도 예외를 던지지 않음
```

### `ui.js`

```js
init()                         // DOM 참조, 저장된 최고 점수, 새 게임, 이벤트 등록
render(state, prevState)       // 타일 DOM을 id 기준으로 재사용·추가·제거, data-value/위치 갱신
handleDirection(direction)     // move → 점수/최고 점수 갱신 → 승리/패배 판정 → render
bindKeyboard()                 // 방향키, WASD, preventDefault
bindSwipe(boardEl)             // 30px 임계값, 주축 판정
showOverlay(kind) / hideOverlay()
updateScore(score, gained)     // +N 표시 포함
```

## 9. 블로그 임베드 계획 (이번 단계에서는 하지 않음)

- **카드 제목**: 숫자 합치기
- **카드 설명**: 같은 숫자를 밀어 합쳐 2048을 만드는 퍼즐. 키보드와 스와이프로 플레이.
- **제안**: 카드에는 **정적 미리보기 이미지(`preview.png`)** + "플레이하기" 링크(`apps/number-merge/`)를 기본으로 함
  - 이유: 목록 페이지에서 iframe이 키 입력·터치 스크롤을 가로채지 않고, 로딩도 가벼움
- iframe을 쓸 경우 대비 사항(지금 구현에 반영):
  - 게임이 처리한 방향키·WASD는 `preventDefault()` → iframe 안팎 스크롤 방지
  - 게임 키 입력은 iframe에 포커스가 있을 때만 동작(브라우저 기본 동작). 보드를 클릭/탭하면 포커스가 들어가도록 보드에 `tabindex="0"`
  - 보드 `touch-action: none`으로 스와이프가 부모 페이지를 스크롤하지 않게
  - iframe 크기 변화(좁은 카드)에서도 레이아웃이 깨지지 않도록 컨테이너 기준 반응형
  - iframe 속성 제안: `loading="lazy"`, `title="숫자 합치기 게임"`

## 10. 검증 항목 (Review 체크리스트)

### 규칙 (`slideLine`/`move`를 콘솔에서 직접 호출해 확인, 왼쪽 이동 기준)

- [ ] `[2,2,2,2]` → `[4,4,_,_]`, 점수 +8
- [ ] `[2,2,4,_]` → `[4,4,_,_]` (새로 생긴 4는 다시 합쳐지지 않음), 점수 +4
- [ ] `[4,4,8,_]` → `[8,8,_,_]`
- [ ] `[2,_,2,_]` → `[4,_,_,_]`
- [ ] `[2,2,2,_]` → `[4,2,_,_]` (앞쪽부터 합침)
- [ ] `[_,_,_,2]` → `[2,_,_,_]`
- [ ] `[2,4,8,16]` → 변화 없음
- [ ] 오른쪽 이동 `[2,2,2,_]` → `[_,_,2,4]`, 위/아래도 같은 원리로 동작
- [ ] 이동 불가 방향 입력 시 타일 생성 없음, 점수 변화 없음
- [ ] 새 타일은 빈 칸에만 생기고 값은 2 또는 4 (`random` 주입으로 0.95 → 4, 0.5 → 2 확인)
- [ ] 빈 칸 없음 + 인접 동일값 없음 → 패배 / 빈 칸 없지만 인접 동일값 있음 → 계속 진행
- [ ] 2048 생성 시 승리 오버레이 1회, "계속하기" 후 다시 뜨지 않음, 이후 이동 정상
- [ ] 새 게임 시 점수 0, 타일 2개, 최고 점수 유지

### 점수판

- [ ] 최고 점수가 새로고침 후에도 유지
- [ ] `localStorage`가 막힌 환경(예: 저장소 차단)에서도 에러 없이 플레이 가능

### 조작·접근성

- [ ] 방향키·WASD 동작, 처리한 키로 페이지가 스크롤되지 않음
- [ ] Ctrl/Meta 조합 키는 가로채지 않음
- [ ] 모바일 에뮬레이션에서 스와이프 4방향 동작, 짧은 탭(30px 미만)은 무시, 페이지 스크롤·당겨서 새로고침 없음
- [ ] Tab만으로 모든 버튼 접근, `:focus-visible` 보임, 오버레이 열림/닫힘 시 포커스 이동
- [ ] `<html lang="ko">`, viewport 메타, 버튼 44×44px 이상

### 디자인·반응형

- [ ] 360px / 768px / 1280px에서 가로 스크롤 없음, 보드 정사각형 유지
- [ ] 라이트/다크 모두 타일 숫자 대비 4.5:1 이상 (값별 계산)
- [ ] 4자리 이상 숫자도 타일 밖으로 넘치지 않음
- [ ] `prefers-reduced-motion: reduce`에서 애니메이션 꺼짐
- [ ] 색상 값이 토큰 밖에 직접 쓰이지 않음
- [ ] 기존 게임의 이름·로고·베이지/주황 팔레트를 쓰지 않음

## 결정 필요

1. **앱 이름**: "숫자 합치기"(가제)로 확정할지, 다른 이름을 쓸지
2. **목표 타일**: 2048로 할지 (다른 값, 예: 1024로 낮출지)
3. **점수 증가 `+N` 표시**: 넣을지 여부 (기본안: 넣음, reduced-motion이면 생략)
4. **진행 중 게임 저장**: 새로고침 시 게임을 이어서 할 수 있게 저장할지 (기본안: 저장 안 함)
5. **테마**: OS 설정만 따를지, 블로그처럼 토글 버튼을 둘지 / 블로그에서 고른 테마(`localStorage`의 `theme`)를 iframe 안에서도 읽어 맞출지
6. **팔레트**: 청록→파랑→보라→자홍 계열 제안안으로 진행해도 되는지
7. **블로그 카드 방식**: 미리보기 이미지 + 링크(기본안) vs. iframe 직접 임베드

## 확정 사항 (2026-11-11 사용자 승인)

위 "결정 필요" 항목은 다음과 같이 확정한다. 본문과 다르면 이 절을 따른다.

1. 앱 이름: **숫자 합치기**
2. 목표 타일: **2048**
3. `+N` 표시: **넣음** (reduced-motion이면 생략)
4. 진행 중 게임 저장: **하지 않음** (최고 점수만 저장)
5. 테마: **블로그 테마를 따름**. `index.html`의 `<head>` 인라인 스크립트에서 `localStorage`의 `theme` 값(`'dark'`/`'light'`)을 읽어 `document.documentElement.dataset.theme`에 설정 (`try/catch`). 값이 없으면 OS 설정(`prefers-color-scheme`). 앱 자체 토글 버튼은 두지 않음. 블로그에서 테마를 바꾸면 `storage` 이벤트로 iframe 안에도 반영.
6. 팔레트: **청록→파랑→보라→자홍 제안안**으로 진행
7. 블로그 카드: **iframe 직접 임베드**. `preview.png`는 만들지 않음
