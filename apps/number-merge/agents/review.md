# Review 서브에이전트 지침 — 숫자 합치기

## 역할

Build 서브에이전트가 만든 웹앱을 **독립적으로** 검증하고 결과를 `apps/number-merge/review.md`에 기록한다. 직접 코드를 고치지 않는다 (수정은 Build 쪽에서 한다).

## 수정 가능한 범위

- `apps/number-merge/review.md` 파일 하나만 새로 만든다.
- 앱 코드(`index.html`, `style.css`, `game.js`, `storage.js`, `ui.js`)와 그 밖의 모든 파일은 읽기만 한다. git 커밋을 하지 않는다.
- 확인용 스크립트는 저장소 밖 임시 디렉터리에 둔다.

## 기준 문서

- `apps/number-merge/spec.md` — 특히 10절 "검증 항목" 체크리스트와 맨 끝 "확정 사항"(본문보다 우선)
- `CLAUDE.md` — 웹앱 규칙(자체 완결, 모바일 사용 가능)

## 검증 방법

1. **코드 리뷰**: 버그, 엣지 케이스, spec과의 차이, 코드 스타일(ES 모듈, 2칸, 세미콜론, 작은따옴표, 전역 변수 금지, 색은 토큰만, `!important`·ID 선택자 스타일 금지), 절대 경로 사용 여부.
2. **로직 테스트**: `node`로 `game.js`를 import해 spec 10절의 규칙 케이스를 직접 실행한다. Build가 쓴 테스트를 재사용하지 말고 새로 작성한다.
3. **브라우저 확인**: 내장 브라우저 미리보기 도구로 `.claude/launch.json`의 `blog` 설정(포트 8000)을 시작하고 `http://localhost:8000/apps/number-merge/`를 연다.
   - 콘솔 에러, 렌더링, 키보드 이동, 점수/최고 점수 갱신, 새로고침 후 최고 점수 유지
   - 승리·패배 오버레이 (JS로 상태를 조작할 수 없다면 코드 리뷰와 로직 테스트로 대신하고 그렇게 적는다)
   - 360px / 768px / 1280px 폭에서 가로 스크롤 없음, 보드 정사각형
   - 라이트/다크 모드 (`colorScheme` 에뮬레이션, `localStorage.theme` 값 `dark`/`light`), 타일 대비(특히 다크 16과 32의 구분)
   - 모바일 프리셋에서 버튼 44×44px 이상
   - 확인이 끝나면 뷰포트를 desktop으로 되돌리고 시작한 미리보기 서버를 종료한다.
4. **iframe 대비**: 다음 단계에서 블로그 카드에 iframe으로 넣을 예정이다. 좁은 폭(약 320~680px)에서도 레이아웃이 유지되는지, 방향키 `preventDefault`가 적용되는지 확인한다.

## review.md 형식

```
# Review — 숫자 합치기
## 요약 (통과 / 수정 필요)
## 발견한 문제 (심각도: 높음/중간/낮음, 파일:줄, 재현 방법, 제안 수정)
## 체크리스트 결과 (spec 10절 항목별 ✅/❌/⚠️ 확인 못함 + 이유)
## 확인하지 못한 것
```
