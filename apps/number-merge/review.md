# Review — 숫자 합치기

검토일: 2026-11-11 · 검토 대상: `index.html`, `style.css`, `game.js`, `storage.js`, `ui.js`

## 요약 (통과 / 수정 필요)

**수정 필요** (가벼운 수정 1건)

게임 로직, 점수·최고 점수 저장, 키보드·스와이프, 승리·패배 오버레이, 반응형, 테마 연동, iframe 대비는 모두 정상입니다.
고칠 것은 하나입니다. **다크 모드에서 8·16·32 타일 배경색이 거의 같아** 색만으로는 구분이 안 됩니다.
그 밖에 `.claude/launch.json`이 앱 폴더 밖에서 수정돼 있는데, 누가 바꿨는지 확인이 필요합니다.

## 발견한 문제

### 1. [중간] 다크 모드 8 / 16 / 32 타일 색 구분이 거의 안 됨
- 파일: `style.css:67-73` (그리고 같은 값을 반복하는 `style.css:109-113`)
- 현상: 다크 배경색이 8 `#2f766d`, 16 `#0d837a`, 32 `#0f766e`입니다. CIELAB 색차(ΔE)가 16↔32 **5.4**, 8↔32 **4.7**, 8↔16 **8.3**으로, 나란히 놓아도 거의 같은 청록으로 보입니다(스크린샷으로 확인). 다른 인접 단계는 ΔE 10~85입니다. 라이트 모드는 16↔32가 30.1이라 문제없습니다.
- 재현: OS 다크 모드(또는 `localStorage.theme = 'dark'`)에서 8, 16, 32 타일을 한 화면에 띄워 봅니다.
- 제안: 8은 더 밝고 채도 낮게, 32는 더 짙게 벌립니다. 예: 8 `#2b5f59`(fg `#f0fdfa`), 16 `#0d837a` 유지, 32 `#115e59`(흰 글자 대비 약 7.6:1). 바꾼 뒤에도 4.5:1 이상인지 다시 계산합니다. spec 6절 표 값과 달라지므로 주석으로 이유를 남깁니다.

### 2. [중간 · 확인 필요] 앱 폴더 밖 파일 수정: `.claude/launch.json`
- `git diff` 결과 `blog-alt`(포트 8123) 설정이 추가돼 있습니다. Build 지침은 `.claude/` 수정을 금지합니다. 이 리뷰가 시작되기 전부터 있던 변경이라 Build가 바꾼 것인지 메인 에이전트가 바꾼 것인지 알 수 없습니다.
- 제안: 작성자를 확인합니다. Build가 바꿨고 필요 없는 설정이면 되돌리고, 필요하면 의도한 변경으로 남깁니다. 앱 동작과는 관계없습니다.

### 3. [낮음] 합쳐진 타일이 이동이 끝나기 전에 새 값으로 먼저 보임
- `ui.js:111-113`, `style.css:375-377`. 합쳐진 새 타일은 목적지에 바로 생기고(`z-index: 2`), 원래 두 타일은 그 아래로 100ms 동안 미끄러집니다. `tile-pop`은 0% 키프레임이 `scale(1)`이라 delay 동안에도 보입니다. 그래서 이동이 끝나기 전에 결과 값이 먼저 나타납니다.
- 제안: 합쳐진 타일에도 delay 동안 `opacity: 0`을 주거나(`0%{opacity:0}` 뒤 바로 1) `tile-appear`처럼 처리합니다. 장식 수준의 문제입니다.

### 4. [낮음] 마우스로 드래그하다 보드 밖에서 놓으면 스와이프가 무시됨
- `ui.js:205-221`. `setPointerCapture`가 없어서, 마우스 `pointerup`이 보드 밖에서 일어나면 받지 못합니다. 터치는 암묵적 캡처가 있어 영향이 없습니다.
- 제안: `pointerdown`에서 `boardEl.setPointerCapture(event.pointerId)`를 호출합니다.

### 5. [낮음] 오버레이 포커스 가두기 없음
- `index.html:44`. `role="dialog"`인데 `aria-modal`과 포커스 트랩이 없습니다. Tab으로 오버레이 밖(헤더 "새 게임", 보드)으로 나갈 수 있습니다. 방향키는 오버레이가 열린 동안 무시되므로 게임 진행에는 문제가 없습니다.
- 제안: `aria-modal="true"`를 붙이고, 열린 동안 보드에 `inert`를 주는 정도로 충분합니다.

### 6. [낮음] 점수 값 `<span>`에 `aria-labelledby`
- `index.html:26,30`. 일반 `span`(generic role)에는 accessible name이 지원되지 않아 스크린리더가 무시할 수 있습니다. 라벨과 값이 이미 붙어 읽히므로 제거하거나 `<dl>`/`<output>` 구조로 바꾸면 됩니다.

### 7. [참고] iframe 높이
- 폭 320px iframe에서 문서 높이는 약 618px, 폭 680px에서는 약 760px입니다. Embed 단계에서 iframe 높이를 이에 맞추지 않으면 iframe 안에서 세로 스크롤이 생깁니다(가로 스크롤은 없음).

## 체크리스트 결과

로직은 `node`로 `game.js`를 import해 새 테스트를 작성해 확인했습니다(저장소 밖 임시 폴더). 33개 중 32개가 통과했습니다. 나머지 1개(오른쪽 이동 `row0`)는 테스트를 잘못 쓴 것입니다. 주입한 난수 0이 새 타일을 (0,0)에 놓았기 때문이고, 이동 결과 자체는 `[_,_,2,4]`로 맞습니다.
UI는 `localhost:8000`에서 확인했습니다. 승리·패배 오버레이만은 저장소 밖 임시 복사본에서 확인했습니다. 복사본의 `ui.js`에 상태를 노출하는 한 줄만 추가해 보드를 직접 설정했습니다.

### 규칙
- ✅ `[2,2,2,2]` → `[4,4,_,_]`, +8
- ✅ `[2,2,4,_]` → `[4,4,_,_]`, +4
- ✅ `[4,4,8,_]` → `[8,8,_,_]`
- ✅ `[2,_,2,_]` → `[4,_,_,_]`
- ✅ `[2,2,2,_]` → `[4,2,_,_]`
- ✅ `[_,_,_,2]` → `[2,_,_,_]`
- ✅ `[2,4,8,16]` 변화 없음 (추가 확인: `[8,8,8,8]`→`[16,16,_,_]`, `[2,_,_,2]`→`[4,_,_,_]`)
- ✅ 오른쪽 `[2,2,2,_]` → `[_,_,2,4]`, 위·아래 동작
- ✅ 무효 이동: `moved=false`, 같은 state 객체 반환, 타일·점수 변화 없음
- ✅ 새 타일은 빈 칸에만 생성(무작위 2000판×30수에서 겹침 0건), 0.95→4, 0.5→2, `random()=1`도 안전
- ✅ 패배 판정 / 빈 칸 없어도 인접 동일값 있으면 계속 진행
- ✅ 2048 생성 시 승리 오버레이 1회, "계속하기" 뒤 다시 뜨지 않음, 이후 이동 정상(브라우저 확인)
- ✅ 새 게임: 점수 0, 타일 2개, 최고 점수 유지(브라우저 확인)
- 추가: 입력 state를 변경하지 않음(불변), 타일 id 중복 없음, `mergedFrom` 정확, `SIZE=3`에서도 동작

### 점수판
- ✅ 최고 점수가 새로고침 후에도 유지됨(`number-merge:best`)
- ✅ 저장소 차단: `loadBest`/`saveBest`, head 인라인 스크립트, `storage` 이벤트 처리 모두 `try/catch` 처리(코드 리뷰로 확인, 실제 차단 환경은 미재현)

### 조작·접근성
- ✅ 방향키·WASD 동작. 대문자, 한글 IME(`ㅈ` + `KeyW`)도 동작하고 처리한 키에 `preventDefault` 적용
- ✅ Ctrl/Meta 조합 키는 가로채지 않음, Enter는 버튼 동작 유지
- ✅ 스와이프 4방향 동작, 30px 미만 탭은 무시(합성 PointerEvent로 확인). `touch-action: none`, `overscroll-behavior: none` 적용
- ✅ 오버레이가 열리면 첫 버튼에 포커스, 닫히면 보드로 포커스 복귀, 열린 동안 방향키 무시. `:focus-visible` 스타일 있음 (포커스 트랩 없음: 문제 5)
- ✅ `<html lang="ko">`, viewport 메타 있음, 버튼 81×57px(모바일 프리셋)

### 디자인·반응형
- ✅ 320 / 360 / 768 / 1280px 모두 `scrollWidth`가 화면 폭과 같음. 보드 288 / 328 / 440 / 440px 정사각형, 360px에서 좌우 여백 16px
- ✅ 타일 숫자 대비: 라이트 최저 5.36(64), 다크 최저 4.60(2048), 4.62(16). 모두 4.5:1 이상
- ⚠️ 다크 16과 32의 구분: 대비는 충분하지만 배경색이 거의 같음(문제 1)
- ✅ 4~6자리 숫자가 타일 안에 들어감(360px에서 131072도 글자 폭 64px, 타일 70px)
- ✅ `prefers-reduced-motion`: CSS로 전환·애니메이션·`+N`을 끄고 JS도 `+N` 생략, 합쳐질 타일 즉시 제거(코드 리뷰로 확인, 에뮬레이션은 하지 않음)
- ✅ 색상은 `:root` 토큰에만 있음. `!important`, ID 선택자, 절대 경로 없음
- ✅ 기존 게임의 이름·로고·베이지/주황 팔레트를 쓰지 않음

### 기타
- ✅ 콘솔 에러 없음
- ⚠️ 앱 폴더 밖 수정: 블로그 `css/`·`js/` import는 없음. 다만 `.claude/launch.json`이 수정돼 있음(문제 2)
- ✅ 연타: 150회 이상 연속 입력 후 DOM 타일과 state가 일치(겹침·누락 없음)
