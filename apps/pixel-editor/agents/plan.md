# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 역할

웹앱 구현 계획(spec)을 작성한다. **코드는 작성하지 않는다.**

## 수정 가능한 범위

- `apps/pixel-editor/spec.md` 파일 하나만 새로 만든다.
- 그 밖의 파일은 읽기만 한다.

## 사용자 요청

> 16×16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있게 해줘. 색상 팔레트도 넣어줘.

## 전제와 제약

- 저장소: 마크다운 블로그 + 미니 웹앱 포트폴리오 (`CLAUDE.md` 참고). 순수 HTML, CSS, JavaScript만 사용, 빌드 도구 없음.
- 웹앱은 `apps/pixel-editor/` 안에서 자체 완결 (블로그의 `css/`, `js/`를 import하지 않음). 외부 라이브러리 없이 만드는 것을 기본으로 한다 (PNG 저장은 `<canvas>` + `toBlob`으로 충분).
- 상대 경로만 사용 (GitHub Pages 하위 경로 배포).
- 모바일에서도 사용 가능: 마우스와 터치(Pointer Events) 모두로 그리기, 드래그로 연속 칠하기, 그리는 동안 페이지 스크롤 방지. 360px 폭에서 가로 스크롤 없음, 터치 대상 44×44px 이상.
- 블로그와 어울리게: 라이트/다크 모드, 색상은 CSS 변수 토큰, `prefers-reduced-motion` 존중, `<html lang="ko">`, 키보드 접근성.
- **테마**: 이전 앱(`apps/number-merge/`)과 같은 방식. `<head>` 인라인 스크립트로 `localStorage`의 `theme`(`'dark'`/`'light'`)을 읽어 `data-theme` 설정, 없으면 OS 설정, `storage` 이벤트로 블로그 테마 변경 반영. 앱 자체 토글 없음. 참고용으로 `apps/number-merge/index.html`, `style.css`를 읽어도 된다.
- **블로그 임베드**: 블로그 메인은 `apps/index.json`에 앱을 등록하면 카드 안에 iframe으로 보여준다 (`js/main.js`, `css/style.css`의 `.app-card-frame` 참고). 이번 앱도 같은 방식으로 넣을 예정이다. iframe 높이를 정할 수 있도록 폭별 예상 문서 높이를 spec에 적는다. iframe 안에서 PNG 다운로드가 동작하는지 검증 항목에 넣는다.

## spec.md에 담을 내용

1. **개요**: 앱 이름(가제), 한 줄 설명
2. **기능**: 그리기(연필), 지우개, 채우기(선택), 스포이드(선택), 전체 지우기(확인 포함), 되돌리기/다시하기(선택), 격자선 표시 토글(선택). 어떤 것을 기본 범위로 넣고 무엇을 선택 사항으로 둘지 제안
3. **색상 팔레트**: 기본 색 개수와 색 목록(특정 기존 제품의 고유 팔레트를 그대로 베끼지 말 것), 사용자 지정 색(`<input type="color">`), 현재 색 표시, 투명(지우개) 처리
4. **PNG 저장**: 출력 크기(16×16 원본 / 확대 배율 선택 여부, 예: ×1·×8·×16), 투명 배경 유지, 이미지 스무딩 끄기, 파일 이름 규칙, 다운로드 방식
5. **화면 구성**: 텍스트 와이어프레임 (모바일 / 넓은 화면). 캔버스, 도구 막대, 팔레트, 저장 버튼 배치
6. **조작**: 마우스·터치(Pointer Events, `pointer capture`, 드래그 시 지나간 칸 사이를 빠짐없이 칠하기), 키보드(도구 단축키, 방향키로 커서 이동 + Space/Enter로 칠하기 등 키보드만으로 그릴 수 있는 방법), 오른쪽 클릭 처리
7. **작업 보존**: 새로고침 시 그림 유지 여부 제안 (`localStorage`, `try/catch`)
8. **디자인**: 색상 토큰(라이트/다크), 투명 칸 표시(체크무늬 등), 선택된 도구·색 표시, 포커스 스타일
9. **파일 구조**: `apps/pixel-editor/` 아래 파일 목록과 책임. 상태·로직(순수 함수)과 UI 분리
10. **핵심 로직 설계**: 데이터 구조(예: 길이 256 배열), 주요 함수 목록과 시그니처
11. **블로그 임베드 계획**: 카드 제목·설명, 폭별 예상 높이
12. **검증 항목**: Review 체크리스트 (그리기·지우기·채우기 엣지 케이스, PNG 크기·투명도·픽셀 정확성, 터치, 360/768/1280px, 라이트/다크, 콘솔 에러, iframe 안 다운로드)
13. **범위 밖**

## 작성 규칙

- 한국어, 간결하게. 사용자가 정해야 할 것은 기본안을 제시한 뒤 "결정 필요" 항목으로 맨 끝에 모은다.
- 작성을 마치면 spec.md 경로와 "결정 필요" 항목(각 기본안 포함)만 짧게 보고한다.
